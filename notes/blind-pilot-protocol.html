Golden rules — break these and the pilot is void
  1. Never sort images into fragmented/elongated folders. That un-blinds you before you rate. Condition lives in a separate file you don't open until rating is done.
  2. Mix multiple sessions per class from the start. One-session-per-condition is what broke the last attempt — the classifier learns "which experiment," not "what shape."
  3. No watershed, no h parameter, anywhere. Every feature is computed on the whole mask or its connected components. If a step needs instance splitting, it's the wrong step.
  4. Hold out by session for validation, never by random image. Images from the same session are near-duplicates.

1Assemble the pilot pool

Pull images without letting condition leak into anything

~50–100 images, deliberately spanning several sessions per class. File names and folders carry no condition information.

1.1

Select candidate images across the archive — not just the CCCP and MAVS-KO/IFN folders used before. Include other fragmenting and elongating conditions if available, spread across multiple imaging sessions each.

1.2

Rename/copy into a neutral pool, keyed by session + serial, never by drug or phenotype: s{session-date}_{serial}.tif.

1.3

Record the true condition for every image in condition_key.csv — kept in a separate folder from the working set, not opened again until Stage 3 is fully done.

data/pilot/ ├── images/ │ ├── s2024-08-20_00001.tif │ ├── s2024-05-20_00007.tif │ └── ... ├── masks/ # filled in during Stage 2 ├── labels_blind.csv # filled in during Stage 3 └── condition_key.csv # true condition — don't open yet

2Hand-annotate segmentation masks

Binary masks only — no per-object labels

Labkit is a few-shot pixel classifier, not manual tracing: scribble examples, it trains live, you correct. The segmentation model only needs mitochondria-vs-background — no instance IDs, since h-free features never need per-object splitting.

2.1

If not installed: Fiji → Help → Update... → Manage update sites → check Labkit → Apply changes → restart Fiji.

2.2

Open the mitochondria-channel MIP (matches what the trained model runs on downstream — not the raw z-stack).

2.3

Plugins → Segmentation → Labkit → open the current image. Add two label classes: mito, background.

2.4

Scribble a handful of strokes on clear mito pixels (bright tubules, dim puncta, edges) with the mito label, a handful on clear background with the other. Don't trace outlines — mark representative examples only.

2.5

Enable live prediction / Train classifier. Labkit overlays its predicted segmentation over the full image.

2.6

Correct wherever it's wrong — add scribbles on missed dim mitochondria or false-positive noise, retrain. Repeat a few rounds until it looks right.

2.7

Export: Show Segmentation → File → Save As → Tiff. Save as {image_id}_mask.tif into data/pilot/masks/.

Speed-up: save the trained classifier after the first 5–10 images and apply it to the next one before scribbling fresh. Correcting an already-decent guess is much faster than starting from nothing each time.

3Blind fragmented / elongated calls

Rate morphology, not memory of the drug

One rater (you), binary scheme for this pilot. The whole point of this stage is that the call reflects what's on screen, not which folder it came from — so the condition file stays closed.

3.1

Work through data/pilot/images/ in randomized order — not grouped by session, not grouped by anything that could let a pattern in file order leak condition.

3.2

For each image: call it fragmented or elongated by eye. If genuinely unsure, it's fine to mark uncertain rather than force a side — note it, don't discard it.

3.3

Log every call in labels_blind.csv: image_id, blinded_call, date_rated. No other columns — nothing that could hint at condition creeping in during later analysis.

3.4

Only after every image is rated: open condition_key.csv and join it against labels_blind.csv for the first time.

If you open the condition file mid-rating, even once, treat the whole blind pass as compromised for the images rated afterward — restart rating for those, don't quietly continue.

4Train the segmentation model

Binary foreground/background, nothing else

Trained model, not the old classical Frangi+Otsu pipeline — masks from Stage 2 are the training targets. Split by session, same rule as everywhere else in this protocol.

4.1

Pair every images/*.tif with its masks/*_mask.tif.

4.2

Split train/validation by session, not by random image — hold out one or two entire sessions the model never sees during training.

4.3

Train a binary segmentation model on the pairs. Output per image: one probability mask, thresholded to binary.

4.4

Check the held-out sessions visually before trusting it on new data — same qualitative overlay check used throughout last round's diagnostics.

5Compute h-free features

Whole-mask and connected-component descriptors only

No watershed, no instance splitting, no h parameter. Everything below is computed on the binary mask straight from Stage 4, or on its connected components — the same set that separated last round's data 12/13 and 13/13 before we knew the labels were confounded.

FeatureWhat it captures
mean_aspect_ratioMajor/minor axis ratio per connected component — elongation, shape-based
mean_eccentricityEllipse eccentricity per component — round vs. stretched
mean_solidityArea ÷ convex-hull area — how filled-in vs. beaded/branchy a shape is
mean_circularity4π·area ÷ perimeter² — compactness
mean_branch_umSkeleton length between topological nodes — use with caution, known compact-object bias (Field Guide, confounds)
mean_net_len_umLength-weighted network size — how big the connected structure a random pixel belongs to typically is
junctions_per_100umBranch-point density — connectivity, not length
endpoints_per_100umFree-end density — inversely tracks network connectedness
largest_net_fracShare of total skeleton length in the single largest network — hyperfusion signal
Compute all of these per image (field) to start, since fields here run 1–4 cells with consistent phenotype. Per-cell breakdown stays available later if that stops holding.

6Train the classifier

Simple and interpretable, sized to the pilot

Logistic regression or a small random forest on the Stage 5 feature table, joined against Stage 3's blind labels. Not end-to-end deep learning — not enough labeled examples yet to justify it, and interpretability is the point at this stage.

6.1

Join labels_blind.csv to the Stage 5 feature table on image_id. Drop any uncertain rows from training, keep them aside as a separate check set.

6.2

Split train/test by session again — same discipline as Stage 4. A model that only works within one session isn't validated.

6.3

Fit logistic regression (or small random forest) on the ~9 features above. Inspect coefficients/importances — they should point at the same features the tools survey flagged as standard (aspect ratio, solidity, connectivity), not something incidental.

6.4

Report accuracy on the held-out session(s), not on training data. This number is the pilot's real result.

7Derive the index and validate

A continuous score, checked against the literature

Not a forced binary. The model's probability output is the fragmentation index — then it gets checked against what the field actually reports, using the Field Guide's definitions table and tool survey as the comparison set.

7.1

Take the classifier's predicted probability (fragmented-class) as the continuous fragmentation index, per image.

7.2

Pick a middle band as ambiguous rather than forcing every score to a side — the boundary itself doesn't need to be sharp for the index to be useful.

7.3

Qualitative check: do the features driving high/low scores match what the PubMed sources in the Field Guide say drives fragmented vs. elongated calls (aspect ratio, form factor, connectivity — not skeleton length alone)?

7.4

Quantitative check: where a paper reports actual values (e.g. solidity ≥0.8 → high fusion propensity, per the solidity/perimeter predictor in the survey), see whether the pilot's own distributions land in a comparable range.

7.5

Write up agreement and disagreement plainly — a mismatch against literature is a finding, not a failure, provided it's a real biological difference and not the compact-object skeleton bias or a session confound creeping back in.
